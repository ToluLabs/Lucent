# Lucent performance audit — 17 November 2026

> Follow-up: [18 November browser acceptance and worker implementation](2026-11-18-acceptance.md) supersedes the outstanding browser/worker items below. This initial measurement record is preserved.

This change implements public-data caching, cheaper reads, bounded list loading,
incremental activity history, lazy circuit loading, safe prover lifecycle handling,
local development timings and submission tracking. No contracts, circuits,
verification keys, Keccak transcript settings or payroll atomicity were changed.

## Measured results and limits

These are **controlled component benchmarks**, except for the explicitly identified
real proof run and public Testnet read. They are not end-to-end browser timings.
Browser-control tools were unavailable during this audit. No financial Testnet
transactions were submitted. Earlier escrow/payment tests do not validate these new
application changes.

## Ranked confirmed bottlenecks

1. **Duplicate, serial read work.** Every read-only contract simulation previously
   fetched a source account before simulating. Payroll lists scanned all templates
   and runs serially; escrow lists read each address and detail serially.
   These are confirmed code paths; the controlled benchmarks quantify their cost.
2. **Route-level refetches and full activity scans.** Pages owned separate effects,
   discarded activity on refresh and restarted event scans from deployment.
   Warm route visits now share public queries; subsequent history reads resume at
   the successful cursor, preserving deduplication and failure safety.
3. **All five circuit artifacts loaded with wallet code.** Reconnection and balance
   display previously imported registration, transfer, withdrawal and both disclosure
   JSON artifacts. Each now has a lazy import, and its prover is reused in-session.
   Browser transfer-byte savings and hydration impact have not been measured.
4. **Unnecessary application context updates.** Every diagnostic log line updated
   React state despite no application UI subscribing to logs. Logs are now a bounded
   session-local ref; financial view updates still publish normally.
5. **Concurrent native backend access and missing disposal.** Prover initialization
   had no single-flight protection, and shared Noir/backend calls were unsynchronized.
   Operations now queue per circuit, keep Keccak enabled and drain before disposal.
   Wallet disconnect disposes initialized prover resources and prevents pending wallet signatures from being submitted after the session closes. This primarily improves
   reliability and memory lifecycle; no claimed numerical memory reduction.
6. **Repeated work in activity rendering.** Search serialized every event on every
   render; escrow metadata resolution covered the full activity history. Search is
   memoized/deferred and uses public searchable fields; only the visible page's
   escrow counterparties are queried.
7. **Confirmation feedback gap.** Hashes became visible only after confirmation;
   the first poll always waited two seconds. A submitted hash is now reported
   immediately, the first status read is immediate, and remaining polling stays
   bounded. Submission/confirmation network errors retain the hash and an ambiguous
   outcome; no automatic resubmission is introduced.

## Query architecture and confidentiality

One QueryClient is created per application provider instance. Keys include network
passphrase, RPC URL, all configured contract IDs, legacy escrow factories, indexer
source, wallet address, resource and identifier. No persistence/dehydration plugin
is installed. Public queries default to 30 seconds stale / five minutes collection,
one read retry, no focus refetch and reconnect revalidation. Recipient status has a
10-second display freshness window and the existing 350 ms debounce.

The cache contains only public registration status, public token balances,
encrypted/public event payloads, template/run metadata and escrow metadata.
Auditor event fetching caches ciphertext only; replay/decryption and viewing keys
remain outside QueryClient. Public contract configuration is already module-scoped.
Authoritative auditor keys, policy/authorization state and commitment reads are
not given time-based caches; concurrent identical simulations alone are shared.

The confidential state engine remains the sole owner of balance openings. Its
mutations are serialized to prevent concurrent sync/merge/spendable writes from
losing updates. Before spending-proof preparation the wallet syncs and verifies
both commitments against a fresh chain read. Cached UI values never replace this.
Payroll witnesses still chain sequentially; only independent recipient reads are
parallelized. A public-balance outage displays Unavailable rather than inventing a
zero or blocking otherwise verified confidential state.

Confirmed actions invalidate related queries in the captured wallet scope:
activity/public balance, payroll metadata on payroll routes, escrow metadata on
escrow routes, and registration checks for other wallet actions. Failed or pending
actions do not invalidate as if successful. Cached public data can remain visible
while revalidating. QueryClient clears on connect/disconnect; generation guards
reject stale connection results, and old-wallet refresh results cannot overwrite
another wallet's view. Pending action guards deliberately survive a reload.

## Timings and pending transactions

Development builds enable SDK timings when the wallet backend loader initializes.
In browser DevTools call `window.__lucentPerformance()` for the last 200 samples.
Entries have only a fixed stage name and duration: read simulation, transaction
simulation, wallet wait, submission, confirmation requests, state sync, wallet
refresh, Noir witness execution, backend construction, proof and verification.
No amounts, inputs, keys, addresses, errors or decrypted records are accepted by
this tracing API. Samples stay local; no telemetry transport is added.

`prover.init` covers constructor/module loading; this pinned bb.js version initializes
WASM/CRS internally during generateProof, so that work is included in `prover.prove`.
Confirmation samples measure individual RPC calls, not total chain settlement time.
React development Profiler/User Timing entries record `lucent.react.render` and
`lucent.navigation.commit`. These are diagnostic commit measurements, not field
vitals or complete hydration measurements. Production tracing is disabled by default.

Submission notifications expose a public transaction hash and do not establish
success. Session storage retains a pending marker and last submitted hash; reload
restores the uncertain guard and explorer link. Multi-step escrow preparation can
have a confirmed last transaction without the whole action being complete.
Therefore recovery still requires checking activity/escrow state and explicit
acknowledgment before retrying; it never automatically marks the whole operation
successful from one transaction hash.

No low-powered device or throttled browser results are claimed. The list tests
emulate slow RPC latency, which is not equivalent to browser network/CPU throttling.
No live full-history indexer was configured; indexer parity remains skipped.
No unseen history is declared complete; missing-range errors preserve history and
cursor and remain visible. Escrow enumeration now propagates unreadable records
instead of silently presenting an incomplete list as complete.

- `packages/app/lib/public-query.tsx`, root layout: scoped QueryClient and reusable hooks.
- Dashboard/send/payroll/escrow/auditor pages: cached public reads and background refresh.
- `lib/event-history.ts`, `lib/concurrent.ts`: incremental event tails and bounded reads.
- `wallet.ts`, `wallet-context.tsx`: lazy artifacts/provers, cleanup, refresh isolation,
  public balance separation, fresh commitment guards and ordered payroll reads.
- SDK client/prover/state engine: read deduplication, timing, transaction ambiguity,
  prover lifecycle and state mutation synchronization.
- Action context/feedback: public submitted hash and reload-safe uncertainty marker.
- Browser fixtures: provider wrappers and mocks updated; not executed this session.

## Regression checks and reproduction

Executed successfully: complete SDK suite (including real register/withdraw/transfer
proofs and 19 disclosure checks), wallet/form/action regression tests, analytics
privacy tests, production build, 51 native contract tests. Native contract suites
include mocks; they are not a security audit or live transaction execution.
New tests cover fresh/deduplicated RPC reads, retry after failed read, wallet decline,
failed/ambiguous confirmation, hash retention, prover serialization/cleanup/Keccak,
query isolation/invalidation/cancellation, bounded ordering/error propagation,
concurrent balance mutations, and incremental event deduplication/failure preservation.

## Further architecture work

- Measure real long tasks before moving Noir witness solving and witness construction
  into a dedicated worker. bb.js already uses workers; moving confidential inputs
  requires deliberate lifecycle, error and account-switch handling.
- Benchmark supported thread counts on the pinned backend and target devices before
  changing the default. Do not change transcript/circuits/VKs for speed.
- Consider idle artifact/backend warmup only after measuring memory/CPU costs; it is
  not enabled speculatively here.
- Replace global registry enumeration with owner-scoped contract/indexer pagination.
  Bounded concurrency improves latency but does not change O(total records) reads.
- A deployed durable indexer is still necessary for reliable full historical recovery.
- Reduce escrow approvals through separately tested contract/proof preparation changes;
  this performance patch does not alter four-step funding authorization.
- Add opt-in, privacy-reviewed field performance aggregation if real adoption warrants
  it; this patch sends no new performance telemetry.
